# Persistence — LLD

**Code:** `internal/store/postgres/`, `internal/controlplane/transactions.go`,
and SQL generated by `sqlc`.

PostgreSQL stores functions, immutable function versions, invocation jobs,
node pools, registered nodes, events, log chunks, and job results. Jobs refer
to a function version. Pool rows contain resource shape, minimum/maximum,
desired count, and idle timeout; node rows refer to a pool. `schema_migrations`
records applied files.

`postgres.Open` configures a bounded `database/sql` connection pool, pings
PostgreSQL, and applies embedded migrations in one transaction. SQL source
in `queries/` is the authority for generated query methods and row types;
run `go generate ./...` after editing a query. Lifecycle operations use the
generic `withTx` helper when a state update and its event/result must commit
together. Conditional SQL predicates protect against stale status and
attempt updates.

The current development policy permits recreating the database after schema
changes; migrations are not a tested backwards-compatible upgrade path for
arbitrary older datasets. The benchmark harness uses a dedicated database
and recreates it per run. Earlier SQLite benchmark results are preserved in
`benchmarks/results/`; their old implementation is available in Git history.

The main runtime exception is node heartbeat recency, which lives in
control-plane memory. PostgreSQL node registration alone does not prove a
node is healthy. Artifact bytes live in S3-compatible storage, while their
keys and version references live in PostgreSQL.
